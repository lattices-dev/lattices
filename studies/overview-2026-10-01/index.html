DESIGN STUDY

Overview: four main-content studies

Same shell, same fixture, demo state only. Nothing here touches the desktop.

The preview is the full 1760×760 window, scaled. Use each study's own Demo state bar for Selected / Out of scope / Empty scope / Editing layer. Keys 1–4 switch studies.

Comparison

StudyImprovesTradeoffs
A · Map TableMonitors on top, a tray of everything else below
  • The lower area becomes a tray: other Desktops, full screen and windows not on a Space are grouped with a reason for each.
  • The verb capsule sits on the selection, so actions are found where you look.
  • The arrange panel shows the per-monitor split and what's left out before you Tile or Distribute.
  • Overlapping windows hide labels on the map (realistic, but busy).
  • The floating capsule can cover map content; it needs careful anchoring.
  • Space peeking adds a mode ("Back to live").
B · WorkbenchQuery bar, table, inspector
  • Best at scale and from the keyboard (↑/↓, ↵, /). Every window is one readable row.
  • A selection outside the scope is a pinned row with its reason and Show in scope.
  • The inspector gives every verb a fixed, labelled home, layers included.
  • Loses spatial truth: the desk strip is a thumbnail, not the main view.
  • The densest of the four; it reads like a database, not a desk.
  • Group-level Tile and Distribute need care so they don't read as global.
C · Desk LanesOne lane per monitor, a column per Space
  • Clearest monitor → Space → window hierarchy. Live versus last known is answered by position: only the current Desktop is a map.
  • Drag a live window onto another Desktop column to move it.
  • Per-monitor Tile and Distribute sit with each monitor.
  • Horizontal pressure: at laptop widths the Space columns narrow and titles truncate.
  • Lane height is fixed per monitor, so a single-Desktop monitor leaves an empty band.
  • Layers are only a filter here; membership lives in a menu.
D · Layer RoomA tab per layer, home Desktop + membership
  • The cleanest split between saving membership (right panel, draft) and arranging (row under the map).
  • Pin, Tuck or Remove start a draft in place, so there's no separate "Edit" mode to find.
  • Saved homes preview where a layer would put its members.
  • Layer-first: browsing windows that belong to no layer is secondary ("No layer" tab, the strip below).
  • Shows one Desktop at a time; other monitors are reachable only through the strip.
  • Saved homes need data the UI doesn't surface today.

Recommendation

Build on A (Map Table). It keeps Overview spatial, which is the one thing a window list can't give, and it fills the empty lower area with the content that was missing: where everything else is and why it can't be arranged.

Borrow from the others. D's membership model: Pin, Tuck and Remove start a draft, with Save kept apart from Arrange. B's pinned "selected outside this scope" row with Show in scope. C's rule that only the live Desktop is drawn as a draggable map, and every other Desktop is read-only.

Leave out for now: Space peek in A, and the saved-homes overlay in D. Both need backend data that isn't exposed yet.

Implementation note

Exists today

  • Scope by monitor, Space, layer and search, independent of selection
  • Focus (switches Desktop when needed) and reveal / Show in scope for an out-of-scope selection
  • Place Left / Right / Max / Center within the window's current monitor
  • Move to Desktop (moveToSpace), live windows only
  • Tile and Distribute over live, eligible windows, with an excluded summary
  • Layer edit → Save, or Save & rearrange (active layer only)
  • Keys: t d ← → / a x

Proposed in these studies proposed

  • A: selection-anchored verb capsule; drag onto Desktop thumbnails; Space peek proposed
  • A: per-monitor arrange preview in the tray proposed
  • B: token query bar; per-group Tile / Distribute; desk strip; ↑/↓ row navigation proposed
  • C: monitor lanes with Space columns; drag between columns; per-lane arrange proposed
  • D: layer tabs; draft started by Pin / Tuck / Remove in place; saved-homes overlay proposed

Every study holds to the same rules. Last-known, off-Space, full-screen, hidden and minimized windows are never offered for bulk arranging or for moving; each one shows why instead. A layer that isn't active can be saved but not arranged.
