Filmstrip details

  • Centered focus. The fixed frame sits halfway down the desktop. The focus backdrop appears immediately when the preview opens and clears when it closes; the strip stays crisp above it.
  • Keep one ahead. A third behaviour: the frame travels, but the strip pans one slot before the edge, so the next desktop is always visible in the direction you're moving (except at the true ends). With "pan at edge", the selected desktop sits against the crop, and you press into a desktop you can't see yet.
  • The rail is now the scrollbar. The original top rail lives under the strip: one cell per desktop, the selected cell bright, and a bracket showing which part of the strip is visible. Position in the whole set stays readable when the strip is cropped.
  • One focus frame, not per-card borders. A single element moves (or stays put in fixed centre). Cards never change size, so nothing reflows on 9→10 or at speed. Cyan ticks on the frame's leading side show direction, then fade.
  • Legibility by distance. Card opacity drops with distance from the selection (1 → .72 → .5 → .36). Each caption carries a large monospaced number, a name and one dot per window. The number and dots stay readable when the thumbnail doesn't.
  • Ends are shapes, not reactions. In fixed centre, the strip shows empty space and a thin end cap past desktop 1 or N. Extra presses do nothing.
  • "You are here." A small cyan dot marks the desktop that is actually showing behind the strip. This keeps browsing and location separate.
  • Plan view. A toggle draws previews as window plans (outline + app label) instead of snapshots, as the image-free option.

Recommendation

Fixed centre, halfway down the desktop. The selected preview stays anchored while neighboring desktops pass through the strip. A restrained backdrop helps the previews hold attention without moving the work underneath. Travel variants remain available for comparison.

Browser illustration vs native evidence

This page shows behaviour, not cost. Nothing here measures native performance. For a native build:

  • Strip and frame: one panel, a CALayer per card, transform-only animation and a gradient mask for the crop. The optional focus backdrop adds a full-stage blur and dim in this browser study. Native compositor cost must be measured; a dim-only layer is a cheaper alternative to compare.
  • Snapshots are the open question: capturing inactive spaces needs ScreenCaptureKit and permission, can be stale and costs texture memory. Decode only the visible cards plus one margin card on each side (at most 8 of 18). Five to eight 336×210 thumbnails are about 1.4–2.3 MB of RGBA. Show the plan, never a blank, while a snapshot is missing or stale.
  • Plans need only per-space window frames and owners (the same data as the Spaces strip). No images are kept.
  • Zones: up to 3 stroked rects on the existing overlay; native cost remains unmeasured.

Limitations

Layouts and thumbnails are invented SVG. Timing is CSS, not Core Animation. Multi-display, full-screen spaces and HiDPI thumbnail cost are not modelled. The desktop is held still by design, so the study does not show a real switch happening underneath.
